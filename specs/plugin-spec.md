# 插件包规范 v1（做任何一条插件都先读这份）

> 立规人：艾小宝 ｜ 依据：师父 2026-09-28 令「先准备好插件和推广事宜，等国庆节后支付接口打通了马上开始」
> 适用范围：`plugins-src/plugins/<编号>-<英文名>/` 下**全部**插件（H / S / L 三级同一套标准）

---

## 一、目录结构（固定，不许自创）

```
<编号>-<英文名>/
├─ SKILL.md             # ① AI 可加载的技能说明（口径、输入、输出、边界）
├─ README.md            # ② 人看的说明（能解决什么 / 怎么装 / 怎么跑 / 样例 / FAQ）
├─ tools/               # ③ 可执行脚本（.mjs / .ps1 / .py），每个都支持 --help
├─ templates/           # ④ 出件模板（csv / md / xlsx 模板）
├─ check/selfcheck.mjs  # ⑤ 自检脚本：跑样例 → 断言输出存在且非空 → 退出码 0/2
├─ samples/             # ⑥ 样例：一份真实输入 + 一份样例出件物
└─ CHANGELOG.md         # ⑦ 版本与变更留痕
```

## 二、编号与命名

- **编号**＝清单编号（`H-01…H-12` / `S-01…S-40` / `L-01…L-60`），目录名用小写：`h01-gov-subsidy-evidence`、`s15-onboarding-compliance`、`l55-audiobook-prooflisten`。
- **版本**：`vMAJOR.MINOR`，首发 `v1.0`；改行为升 MINOR，改输入输出契约升 MAJOR。
- **语言**：代码里的注释用中文（便于师父审阅）；对外文案中英双语齐备。

## 三、三级交付形态（对应清单分级）

| 级别 | tools/ 里通常有什么 | check/ 断言什么 |
|---|---|---|
| **重量级（H）** | 需服务端/多模块，本仓库放**部署说明 + 核心规则库 + 出件引擎** | 规则库自检 + 引擎对样例跑通 |
| **普通级（S）** | 1 个主脚本 + 1 个出件模板 | 样例输入 → 出件物字段齐全 |
| **轻量级（L）** | 1 个脚本或提示词包 + 校验清单 | 样例通过 + 校验清单命中数 |

## 四、SKILL.md 必填七节（AI 与人共用）

1. **适用场景**（行业 + 真实痛点原话）
2. **AI 具体干什么活**（一句话，必须能落到动作）
3. **输入**（格式、来源、最小必需字段）
4. **输出**（出件物名称 + 字段清单）
5. **使用步骤**（命令级，可直接复制）
6. **边界与不适用**（写清"不做什么"，防止被当万能工具）
7. **合规与免责**（辅助不决策 / 需持证人复核 / 数据不出本机）

## 五、口径与红线（写文案、写代码都要守）

1. **不承诺效果**：不写"准确率 XX%""保证通过审核"；已实测写【实测】、口径写【口径】、推断写【估算】。
2. **辅助不决策**：医疗、法律、财务、保险、支付、核安全等场景，出件物顶部必须带「**需持证人复核**」字样。
3. **数据边界**：不采集用户隐私、不代爬、不代刷；需要外部数据一律走官方接口或用户自带账号与密钥，**密钥只从环境变量读，绝不写进包**。
4. **不打包第三方代码**：只做自有实现；确需调用开源项目，只在 README 里给官方仓库链接与安装说明。
5. **可回退**：任何写盘前先备份；破坏性操作必须提供 `--dry-run`。
