# 入职合规核验机器人 · Onboarding Compliance Checker

> **需持证人复核**：本插件出的是「缺失项清单 + 风险台账（底稿）」，不替代 HR 负责人或合规持证人的最终判断，也不判定材料真伪。

## 1. 适用场景
- 行业：人力资源（hr）
- 真实痛点：入职材料散在纸质袋、微信、邮箱里，HR 逐份肉眼比对极易漏件（离职证明、体检有效期、先上岗后签约）；一旦漏了，赔的是**用工风险与仲裁败诉**。
- 谁在用：企业 HR 专员 / HRBP / 人事主管；劳务派遣与门店连锁的人事中台；人力资源外包服务商。

## 2. AI 具体干什么活
把《入职材料登记表》每一条**逐项对照 10 条合规规则**，输出**缺失项清单 + 按人聚合的催办清单 + 风险台账**；每条结论都标注**规则编号**与**登记表行号**，HR 可一眼复核、直接催办。

## 3. 输入
`CSV`（UTF-8，表头如下，缺列按空处理）：

| 字段 | 必需 | 说明 |
|---|---|---|
| 姓名 | 是 | |
| 身份证号 | 是 | 18 位；用于格式校验与年龄核算（仅本地计算） |
| 岗位类别 | 是 | 管理岗 / 技术岗 / 职能岗 / 操作岗 |
| 入职日期 | 是 | YYYY-MM-DD |
| 合同签订日期 | 否 | 晚于入职日期 ⇒ 高风险（先上岗后签约） |
| 劳动合同 | 是 | 已签 / 未签 |
| 身份证复印件 | 是 | 有 / 无 |
| 学历证明 | 视岗位 | 管理岗/技术岗/职能岗 必须有 |
| 离职证明 | 视情况 | 非应届生必须有 |
| 三方协议 | 视情况 | 应届生必须有 |
| 体检日期 | 是 | YYYY-MM-DD；须在入职前 6 个月内 |
| 银行卡 | 是 | 有 / 无 |
| 紧急联系人 | 是 | 姓名即视为已填 |
| 应届生 | 是 | 是 / 否 |

## 4. 输出（出件物）
- `入职合规核验台账.md`：汇总 / **逐人明细（规则+等级+结论+行号）** / 按人聚合的待补整改清单 / 规则口径 / 免责。
- `入职合规核验台账.csv`：字段 `姓名 / 岗位类别 / 入职日期 / 风险等级 / 问题数 / 规则命中 / 问题摘要`。

## 5. 使用步骤
```powershell
# 1) 照 samples\in-onboarding-6p.csv 的列名填自己的数据（列名不要改）
# 2) 先干跑看看（不写盘）
node tools\check-inbound.mjs --in samples\in-onboarding-6p.csv --out out\台账.md --dry-run
# 3) 正式出件
node tools\check-inbound.mjs --in 你的登记表.csv --out out\台账.md --ledger out\台账.csv
# 4) 自测（确认环境没问题）
node check\selfcheck.mjs
```

## 6. 边界与不适用
- **不做**：不核验材料真伪、不查社保/个税/司法记录、不生成劳动合同文本。
- **不适用**：劳务派遣三性岗位的派遣协议审查、外籍员工工作许可（涉及出入境与许可规则，请用专门流程）。
- 规则以中国大陆现行常见用工合规要求为口径（R01–R10），**地方细则与企业内控差异需自行增补规则**。

## 7. 合规与免责
- **辅助不决策**：结论须由 HR 负责人 / 合规持证人复核后采用。
- **数据不出本机**：全部本地运行；身份证号只做**格式**校验（GB 11643 校验位），不代表真伪结论。
- **不承诺效果**：不保证通过劳动监察或仲裁审查；本工具只降低"漏件"概率，不承担用工法律责任。
